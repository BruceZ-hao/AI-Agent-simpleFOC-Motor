# 06 · 1.83" TFT 显示屏（ST7789P3 / 240×284 / 4 线 SPI）

给触觉旋钮加一块本地屏幕：**不用电脑、不用上位机**，直接看模式、角度、转速、输出电压 Uq、弹簧参数和帧率。

## 1.  screen 规格与 8 根线

| 项目 | 值 |
| --- | --- |
| 尺寸 / 分辨率 | 1.83" IPS，**240 × 284**（竖屏） |
| 驱动 IC | **ST7789P3**（与 ST7789V 命令集基本兼容） |
| 接口 | 4 线 SPI（8 针模块，屏幕**只写不读**，没有 MISO） |
| 像素格式 | RGB565，16 bit |
| 逻辑电平 | 3.3V（ESP32-S3 直连，无需电平转换） |
| 外形 | **四周圆角、像手表屏**；玻璃 R≈4mm（规格常写 `R0.4`，按 0.4cm≈4mm 解读）。GRAM 仍是完整 240×284 矩形，四角必须由固件刷黑、由面板开孔切圆 |

8 针模块常见丝印与含义（不同厂丝印可能写成 `SCLK/SDI/AO/RS/LEDA`）：

| 屏脚 | 含义 | ESP32-S3 DevKitC-1 |
| --- | --- | --- |
| `GND` | 地 | **GND**（必须与驱动板、AS5600 共地） |
| `VCC` | 电源 | **3V3**（若模块带 LDO 且标注 5V 容忍，也可接 5V；先按 3V3 试） |
| `SCL` | SPI 时钟 | **GPIO12**（S3 默认 SCK） |
| `SDA` | SPI MOSI | **GPIO11**（S3 默认 MOSI） |
| `RES` | 复位，低有效 | **GPIO15** |
| `DC` | 命令 / 数据选择 | **GPIO14** |
| `CS` | 片选，低有效 | **GPIO10**（S3 默认 SS） |
| `BLK` | 背光 | **GPIO16**，默认普通 GPIO 常高（无纹波）；`TFT_BL_PWM=1` 才启用 LEDC 5kHz PWM 调光 |

> `MISO = GPIO13` 只是固件里给 SPI 总线占的一个空闲脚，屏上没有这根线，**不用接**。

### 为什么是 10~16

S3 已被占用的脚：电机 3PWM `4/5/6` + EN `7`，AS5600 `I²C 8/9`；禁区 `0/3/45/46`（strapping）、`19/20`（原生 USB）、`26~32`（Flash）、`33~37`（部分批次 octal PSRAM）、`43/44`（UART0）、`48`（板载 RGB）。

`10/11/12/13` 恰好是 Arduino-ESP32 3.x 给 S3 定义的默认 `SS/MOSI/SCK/MISO`，走默认 FSPI 不需要 GPIO 矩阵重映射，时序最稳；`14/15/16` 是普通空闲 GPIO。**两组完全不冲突**，接屏不需要动原来的任何一根线。

## 2. 为什么不用现成图形库

本机 Arduino 库目录里只装了 Simple FOC；TFT_eSPI / Arduino_GFX / Adafruit_GFX 都要另外装库、改 `User_Setup.h`，而且 240×284 是非标准尺寸，很多库的 `init(240,284)` 显存偏移对不上。

所以固件自带两个头文件，**零第三方依赖**：

| 文件 | 职责 |
| --- | --- |
| `ESP32S3_SimpleFOC_AS5600/TFT_ST7789P3.h` | SPI 初始化、CASET/RASET 窗口、RGB565 填充 / 线 / 圆 / 5×7 字模、测试图、GPIO/PWM 双模式背光、`reinit()` 运行时换速 |
| `ESP32S3_SimpleFOC_AS5600/TFT_UI.h` | 仪表盘布局、`DisplayState` 快照、core 0 渲染逻辑 |

### 双核分工（关键）

SPI 刷屏是**阻塞**传输，整屏 240×284×2 ≈ 136 KB，绝不能放进 `loop()`——那会打断 `loopFOC()` 的高频电流环，电机手感立刻变糙甚至抖动。

```text
core 1 : setup() / loop() / loopFOC() / move() / Commander
         └─ 每轮只写 DisplayState 里的几个 float（32 位对齐，原子读写，无需加锁）
core 0 : tftTask (priority 1, 20 FPS)
         └─ 帧首应用 V/I/C/N/O/Q/P/W 命令标志 → 静态背景 → 动态控件 → 四角圆角遮罩 → 统计 FPS
```

串口命令回调运行在 core 1，它们**只置标志位**，真正的 SPI 操作由 core 0 在帧首统一执行，杜绝双核抢总线。

## 3. 第一次上电：先只测屏（STAGE 0）

不要把屏幕和电机一起第一次上电。把 `.ino` 顶部改成：

```cpp
#define STAGE   0
#define USE_TFT 1
```

编译上传后 **Wire / driver / motor 全部不初始化**，电机不上电、不做 `initFOC()` 对齐。屏幕先显示 **2.5 秒白底 + 橙块 + 蓝块的高对比开机画面**（用来确认初始化和第一帧 SPI 是通的），随后进入测试图（一个橙色小方块来回移动证明程序在跑）。这一步能独立验证 8 根线、供电、初始化序列和显存偏移。

> **最快路径**：直接双击 `flash_stage0.bat`，它烧录仓库里预编译的 `ESP32S3_SimpleFOC_AS5600.STAGE0.bin`（4MB 合并镜像），**不用装 Arduino IDE、不用编译、不用接 12V**。
> `flash_and_run.bat` 烧的是 STAGE 3 主固件，两个镜像互不影响，随时可以来回切换。

若要自己从源码编译（例如改了 `TFT_*` 参数）：

```bat
arduino-cli compile --fqbn "esp32:esp32:esp32s3:CDCOnBoot=cdc,UploadSpeed=115200" ^
  --output-dir ESP32S3_SimpleFOC_AS5600/build ESP32S3_SimpleFOC_AS5600
```

## 4. 屏幕校准（不用重新编译）

下面这些命令在**两种情况下都能用**：

- **STAGE 0 镜像**：完全不碰电机，第一次接线时推荐。
- **STAGE 3 主固件但没接 12V**：上电 `initFOC()` 会失败，固件**不再卡死**——串口打印 `Motor outputs DISABLED`，屏幕模式标签显示 `FOC FAIL`，电机输出已禁用，但 `V/I/C/N/O/Q/P/W` 和串口诊断照常响应，可以先专心把屏幕调好。接好 12V / 三相线并让轴空转后**按一下板子 RESET** 就会重新校准并进入弹簧回中，不用重烧。

STAGE 0 下用串口 115200 发这些命令，效果立刻生效：

| 命令 | 作用 | 什么时候用 |
| --- | --- | --- |
| `V` | 测试图开关：四边 **1px 白框** + 8 色条 + 四角定位块 + 左侧刻度 + 当前参数 | **首先发这个** |
| `O<col>,<row>` | 修改显存偏移，例如 `O0,20`、`O0,36` | 白框缺边 / 画面整体往右下偏 / 底部一条花屏 |
| `I` | 反色 INVON / INVOFF 切换 | 白底黑字反了、颜色发灰 |
| `C` | RGB / BGR 顺序切换 | **红色变蓝色**（或反之） |
| `N` | 背光开关 | 背光不亮时先确认是否只是被关掉 |
| `Q<MHz>` | 运行时改 SPI 速率并重新初始化屏幕，例如 `Q2` / `Q4` / `Q8` | **不用重新编译**就能逐级换速，找最高稳定档；噪多发 `Q2`/`Q1` 降级 |
| `P` | 冻结 / 恢复 UI：冻结后只保留一帧静态图，不再写 GRAM | **A/B 定位**：冻结后画面稳定 = 持续刷新路径有问题；冻结后仍花屏 = 初始化或硬件问题 |
| `W<px>` | 圆角屏四角遮罩半径（像素），例如 `W30` / `W20`；`W0` = 关闭遮罩回直角 | 玻璃是圆角手表屏：测试图里的**红色圆弧**就是当前遮罩边界，调到刚好贴住玻璃圆角 |

判断方法：

1. **四边白框必须完整闭合**。缺上边/左边=起始地址偏了；缺右边/下边=分辨率大于实际可见区或偏移过大 → 用 `O` 调，或把 `TFT_ROW_OFS` 改成 20 / 36 之类再编译。（圆角屏四角本来就被玻璃切掉，遮罩范围内没有白框角是正常的。）
2. **彩条顺序**应是 白 / 红 / 绿 / 蓝 / 青 / 品红 / 黄 / 黑。若红蓝互换 → 发 `C`。
3. **黑白颠倒** → 发 `I`。
4. 全黑但背光明显亮着 → 先发 `P` 冻结成单帧静态图：**冻结后仍黑**就是接线问题（`SCL/SDA` 接反、`RES` 悬空、`CS/DC` 互换、VCC 不是 3.3V），逐根核对第 1 节接线表；**冻结后出图**则是持续刷新或速率问题，发 `Q2`/`Q1` 降速。
5. 花屏 / 闪屏 → 先确认用的是 **DC 修复版**（2026-11-15 后）：旧版 `setWindow()` 发完 `RAMWR` 没把 DC 拉回高电平，像素全被当成命令，必然花屏。若已是修复版，再查杜邦线过长 / 未共地，给 VCC 并 10µF + 100nF，并用 `Q2`/`Q1` 逐级降速。
6. **四角有直角亮块 / 左上标题被切半个字** → 圆角半径不对，发 `V` 进测试图看红色圆弧，用 `W<px>` 调（见下节）。

### 圆角屏（手表屏）适配

物理玻璃是四周圆角，但 ST7789P3 的 GRAM 仍然是完整的 240×284 矩形。如果按普通直角屏画图，四角会出现直角亮块露在玻璃外面，标题、模式标签这些靠边的文字也会被切掉。固件做三件事：

| 层 | 处理 |
| --- | --- |
| 驱动 `TFT_ST7789P3.h` | `applyCornerMask(r, bg, edge)`：按 `x²+y²=r²` 逐行算出四角该遮掉的水平宽度，各刷一条 1px 高底色矩形。测试图传 `edge=TFT_RED` 时沿边界补 1px 红线，便于肉眼对齐玻璃圆角 |
| UI `TFT_UI.h` | 静态帧画完、每帧动态刷新结束**都重涂一次**遮罩（动态绘制会擦掉顶部角落）；`SIMPLEFOC` 标题移到 x=34、行标签移到 x=10，避开圆角 |
| 3D 面板 `Enclosure/enclosure.py` | 正面视窗 cutter 用 `rounded_rect_poly(..., tft_win_r)` 切成圆角矩形，而不是直角 `box`，否则打印件的窗口四角会露出直角边 |

半径换算（可视区约 30.5mm 宽 / 240px ≈ **0.127 mm/px**）：

| 玻璃 R | 像素半径 | 命令 |
| --- | --- | --- |
| 0.4 mm（若规格 `R0.4` 指 0.4mm） | ≈3 px | `W3` |
| **4 mm（`R0.4` 按 0.4cm 解读，手表屏常见）** | **≈31 px → 默认 `W30`** | `W30` |
| 6 mm | ≈47 px | `W47` |

校准步骤：发 `V` 进测试图 → 看红色圆弧是否正好贴住玻璃圆角 → 偏大（黑角明显吃掉画面）发 `W20`，偏小（圆角外仍有亮像素）发 `W40`/`W47` → 对齐后把值写回 `.ino` 的 `TFT_CORNER_PX`，并同步改 `Enclosure/enclosure.py` 的 `tft_win_r = px × 0.127` mm，跑 `regen.bat` 重出 STL。`W0` 可随时退回直角模式。

调好后把稳定值写进 `.ino` 的 `TFT_COL_OFS / TFT_ROW_OFS / TFT_INVERT / TFT_BGR / TFT_CORNER_PX`，然后 `#define STAGE 3` 重新编译。

## 5. 仪表盘上有什么（240×284 竖屏）

```text
┌────────────────────────────────┐
│ SIMPLEFOC          [HAPTIC]    │  模式标签
├────────────────────────────────┤
│ +123.4 deg                 DEG │  大字角度（相对 home）
│          ╭────────╮            │
│        ╭─╯   ↑    ╰─╮          │  表盘：指针 = 轴角 mod 2π
│        │      ●     │          │  顶部橙色刻度 = 原点
│        ╰────────────╯          │
│ Uq  ┃━━━━━━━┿━━━┃             │  力矩条：中点 0，左负右正
├────────────────────────────────┤
│ MODE  HAPTIC S1                │
│ TGT   +0.00 rad                │
│ VEL   +0.00 r/s                │
│ UQ    +0.00 V                  │
│ K/Z   K8.0 Z0.012              │
│ SENS  OK S1 20FPS              │
└────────────────────────────────┘
```

- 示意图画成直角只是便于阅读：实际四角已按手表屏圆角刷成底色，标题与行标签都挪进了圆角安全区。
- `TGT` 在 `M1` 下是相对原点的角度 [rad]，在 `M0` 下是目标速度 [rad/s]。
- 力矩条满量程 = 当前 `motor.voltage_limit`（`L` 命令改它，条也跟着变）。
- `SENS` 行显示 AS5600 是否初始化成功、静音刹车开关、实际刷新帧率。
- 板载 WS2812 状态灯、上位机、串口 `Commander` **全部照旧可用**，屏幕只是多一路只读显示。

## 6. 参数区

| 宏 | 默认 | 说明 |
| --- | --- | --- |
| `USE_TFT` | `1` | 改成 `0` 完全不编译显示代码，固件退回纯串口版本 |
| `STAGE` | `3` | `0` = 只测屏（不碰电机） |
| `TFT_SCK/MOSI/MISO/CS/DC/RST/BL` | `12/11/13/10/14/15/16` | 8 针接线，改脚位须全部避开禁区 |
| `TFT_SPI_HZ` | `4000000UL` | 4MHz：整屏 GRAM 约 0.27s，比 1MHz 的 1.1s 少很多「半刷新」时间。DC 修复后可稳跑；长线噪多发 `Q2`/`Q1` 降级，稳定档写回这里 |
| `TFT_BL_PWM` | `0` | `0`=BLK 普通 GPIO 常高（无 PWM 纹波，默认）；`1`=LEDC 5kHz 调光。5kHz / 80~150mA 脉动会通过共用 3V3/GND 长线干扰 SPI |
| `TFT_UI_CORE` | `0` | 刷屏任务所在核；怀疑 SPI 跨核访问问题时可改 `1`（会与 `loopFOC()` 抢 core 1） |
| `TFT_W/TFT_H` | `240/284` | 面板分辨率 |
| `TFT_COL_OFS/TFT_ROW_OFS` | `0/0` | 显存窗口偏移，也可用 `O` 命令运行时调 |
| `TFT_INVERT/TFT_BGR` | `1/1` | 反色 / BGR，也可用 `I` / `C` 命令切换 |
| `TFT_FPS_MS` | `150` | ~6 FPS；4MHz 下每帧约 0.2s 的 GRAM 写入，避免屏幕长时间停在半刷新状态 |
| `TFT_CORNER_PX` | `30` | 圆角屏四角遮罩半径 [px]（R4mm ≈ 31px）。`0`=直角模式；运行时 `W<px>` 可实时调，见第 4 节圆角屏适配 |

## 7. 常见问题

| 现象 | 排查 |
| --- | --- |
| 圆角处有直角亮块 / `SIMPLEFOC` 标题被切半个字 | 圆角半径不匹配：发 `V` 进测试图看红色圆弧，用 `W20` / `W40` 调（默认 `W30` ≈ R4mm）；对齐后写回 `TFT_CORNER_PX`，并同步改 `tft_win_r`。详见第 4 节「圆角屏适配」 |
| 背光亮、屏幕全黑（无图像） | ① **最常见：屏幕 VCC/GND 取自电源模块，与 ESP32 的 GND 没可靠共地** → 把屏幕 VCC/GND 直接接 ESP32 板上的 3V3/GND；② `SCL/SDA` 接反、`CS/DC` 互换、`RES` 没接或悬空；③ 先用 `P` 冻结成单帧静态图区分「初始化」与「持续刷新」，再用 `Q2`/`Q1` 降速 |
| `TFT: ST7789P3 ready` 但屏幕不亮 | 这行**只代表初始化命令发出去了**：SPI 只写不读、8 针模组没有 MISO 回读，芯片无法确认屏幕是否收到。不能拿它判断屏幕好坏 |
| 接 12V 后屏幕闪一下就灭 | 电源模块 3V3 带载跌落，或模块地 / ESP32 地 / 驱动板地之间存在电位差。屏幕改由 ESP32 3V3 供电，并确认三处 GND 单点共地 |
| **接好共地后能出图，几秒后整块熄灭（连背光都没了）** | ① 先用万用表量屏幕 VCC **必须是 3.3V**（有些 DC-DC 标 3V3 实际输出 5V，过压会先亮后灭甚至烧屏，立刻断电）；② 背光满亮度电流可达 80~150mA，DC-DC 的 3V3 支路带不住会进保护 → 屏幕 VCC/GND 全部改接 ESP32 板上的 3V3/GND；③ 把 BLK 从 GPIO16 改接 3V3（不经 PWM）验证背光驱动；④ 用 `TFT_HWTEST.bin` 静态画面隔离测试区分供电与软件 |
| **只见花屏，2.5 秒后变黑**（本次实测的根因） | **驱动级 DC 电平错误**：`setWindow()` 发完 `RAMWR(0x2C)` 后，`writeCmd()` 把 DC 留在低电平没有恢复；4 线 SPI 的 D/CX 是**逐字节**采样的，于是 `fillRect / putPixel / drawChar` 发出的**全部像素字节都被屏幕当成命令**：GRAM 一直保持上电时的随机内容 → 花屏；像素流里偶然出现 `0x28`(DISPOFF) 或 `0x10`(SLPIN) → 屏幕被关掉变黑。**与 SPI 速率、背光 PWM、刷屏任务跑哪个核都无关**，所以之前从 20MHz 一路降到 1MHz 都没用。修复：`setWindow()` 末尾补 `digitalWrite(_dc, HIGH)`；所有像素写入都经过它，一处改完全部生效。两份 `TFT_ST7789P3.h`（主目录 + `TFT_HWTEST/`）已同步 |
| **曾误判为「PWM 背光纹波 / 高速 SPI 误命令」** | 隔离测试里「静态一帧能保持」曾让我们把锅甩给 LEDC 纹波与长杜邦线误码，据此加了 `assertDisplayOn()` 每 2 秒重申 DISPON、把速率降到 1MHz，症状依旧。事后看，当时的「白底橙块」很可能是**背光 + 上电随机 GRAM 的误判**，并不能证明第一帧像素数据正确。教训：8 针 SPI 屏没有 MISO、只写不读，`TFT: ready` 只代表命令发出去了；遇到花屏应**先核对 DC/CS 时序**，再动速率和供电 |
| **一打开串口监视器 / 上位机，屏幕就黑一下** | S3 用的是原生 USB CDC，**每次打开 COM 口都会触发 `rst:0x15 (USB_UART_CHIP_RESET)` 芯片复位**，屏幕随之黑 2~3 秒再出开机画面，属正常现象。调屏幕时把 Web 上位机和 IDE 串口监视器都关掉，只看屏幕本身 |
| 屏幕一直黑但串口心跳仍在打印 | 板子没死，是屏幕供电 / 背光 / 屏控芯片掉电。用硬件隔离固件的 `R`（重新初始化）、`B`（翻转 BLK）定位 |
| 只有上半屏有图 / 底部花屏 | 显存行偏移不对，发 `O0,20` / `O0,36` 试；ST7789P3 部分模组可见区从 Y=20 或 Y=36 起 |
| 红蓝互换 | 发 `C` 切 RGB/BGR |
| 黑白颠倒、颜色发灰 | 发 `I` 切 INVON/INVOFF |
| 文字左右镜像 / 上下颠倒 | 本驱动默认竖屏 `MADCTL=0x00`，需要旋转请改 `applyOrientation()` 里的 MADCTL（MV/MX/MY 位），并同步调整 UI 布局坐标 |
| 屏幕闪、电机手感变差 | 先确认没把刷屏放进 `loop()`（本固件已放 core 0）；再发 `P` 冻结看是否消失、把 `TFT_FPS_MS` 调大（降帧率）、用 `Q` 降 SPI 速率 |
| 串口发命令没反应 | 屏和上位机都在用 USB CDC，烧录前关掉 IDE 串口监视器与上位机；波特率 115200、行结束符 `\n` |
| 开机画面停留 2.5 秒后变成仪表盘 | 正常且刻意：刷屏任务现在在 `_delay(2500)` **之后**才创建，这 2.5 秒里 core 0 完全不碰 SPI，白底橙块能完整保持，用来确认「初始化 + 第一帧像素写入」是否正确；之后才画静态仪表盘背景并进入动态刷新 |

### 硬件隔离测试（屏幕亮一会就灭时用）

`ESP32S3_SimpleFOC_AS5600/TFT_HWTEST/` 是一个**独立的 Arduino 工程**（`ESP32S3_TFT_HWTEST.ino` + 同目录的 `TFT_ST7789P3.h` 快照副本，改动主驱动后需同步拷贝）。用 Arduino IDE 打开 `.ino` 直接编译上传即可，或按 `docs/02-firmware.md` 的 `arduino-cli` 命令导出合并镜像（本地已编译好的放在 `build/TFT_HWTEST.bin`，不入库）。它把软件变量全部剥掉：

- 不加载 SimpleFOC / Commander / Wire，电机完全不碰
- `BLK(GPIO16)` 用**普通 GPIO 常高**驱动，完全不用 LEDC / PWM
- SPI 1MHz、只发最简初始化序列（不发厂商扩展寄存器表）
- 开机只画**一帧静态图案**（纯色 + 中间橙块），之后永远不再碰 SPI
- 没有 core 0 刷屏任务、没有动画；每 2 秒打印 `HB t=...ms bl=HIGH pinRead=1`

串口命令：`R` 重新初始化并重画、`B` 翻转 BLK 高低（判断背光是高有效还是低有效）、`C` 换纯色、`H` 立即心跳。

> **重要**：2026-11-15 的 DC 修复已同步到这个快照副本。修复前「静态画面能保持」其实是背光 + 上电随机 GRAM 的误判（像素全被当成命令），所以早期据此得出的「速率 / PWM 纹波」结论不成立。现在用它做隔离测试，纯色块才是真正写进 GRAM 的。

判读表：

| 现象 | 结论 |
| --- | --- |
| 静态图案一直保持、心跳连续 | 屏幕硬件与链路都是好的，问题在正式固件的刷新任务 / SPI 速率 / 初始化表 |
| 图案消失但 `HB` 一直打印 | **屏幕供电或背光掉电**，与 ESP32 软件无关；查 3V3 电压、DC-DC 带载、BLK 接线 |
| 发 `R` 后图案立刻回来，过几秒又灭 | 屏控芯片反复掉电复位（VCC 跌落），或模组进入了 sleep |
| 发 `B` 后反而亮了 | BLK 是**低有效**（LEDK），把 `TFT_BL` 逻辑反相或把背光直接接 GND |

> 测完务必双击 `flash_and_run.bat` 烧回主固件：诊断镜像是 STAGE 0 / 无电机，仪表盘不会被烧进去。

## 8. 机械安装：06 独立 TFT 显示面板

### 为什么没有直接把视窗开在顶盖上

现有 `Enclosure/` 顶盖是 110×76mm，中心已被 Ø42 电机沉台占据，四角是 M3 螺柱，两侧还有 12 个散热孔。把 35×42mm 模组尽量往右推到贴住内腔壁后：

```
右侧可用净宽 = 110/2 - 2.4(壁厚) - 42/2(沉台半径) = 31.6 mm
模组需要     = 35 mm                        → 至少差 3.4 mm
```

也就是说模组左边必定切进电机沉台 3.4mm，右边还会压住 `(±34, 15/20)` 那 4 个散热孔，并逼近螺柱沉头。硬开一个矩形窗口会破坏上一轮刚修好的**平齐口沿 + 四条让位唇边**结合面。所以不去动 01~05 任何一个已通过校验的零件，改为新增第 6 个独立零件 `Enclosure/stl/06_tft_panel.stl`。

### 06 面板结构（`Enclosure/enclosure.py` 的 `tft_*` 参数）

| 部位 | 默认 | 说明 |
| --- | --- | --- |
| 面板外形 | 54×56×3mm，R4 | 正面朝平台打印，背面结构朝上，免支撑 |
| 正面视窗 | 30.5×36mm | 比推算的可视区 30×35.5 略大，不遮边缘像素；四周留 2.25 / 3.0mm 压边压住 PCB |
| 背面限位框 | 内 35.4×42.4、外 38.6×45.6、深 2.2mm | 模组每边留 0.2mm 间隙嵌进去；下边留 14mm 缺口给 8 根 SPI 排线 |
| M2 自攻柱 | 4 × Ø3.2，孔 Ø1.6，坐标 (±23, ±25) | 配小压片 + M2 螺钉压住 PCB 四角，或直接点热熔胶 / 双面胶 |
| M3 安装孔 | 2 × Ø3.4，坐标 (±23, 0) | 用 M3 螺钉把整块面板锁到外壳侧面、铝型材、L 型角板或台面支架 |

`Enclosure/verify_fit.py` 已把视窗四边、限位框内外墙、排线缺口、柱孔、安装孔壁厚和柱与限位框的干涉都做成自动检查；`render/10_tft_panel_front.png` 与 `11_tft_panel_back.png` 是正面与背面特写（橙色只标背面限位框与 4 个柱，面板本体浅灰；背面仰视时 Y 方向镜像，下边的排线缺口在图上显示在上方）。

### 装法（按需选一种）

1. **外接调试（推荐第一步）**：先用杜邦线把屏挂在壳外，按第 4 节校准好偏移 / 反色 / BGR，再装面板，避免反复拆装。
2. **独立台面 / 支架**：2 个 M3 孔锁到 L 型角板或铝型材，摆在旋钮旁边，位置随意；这是 06 面板的默认用法，**不用重打外壳**。
3. **锁到外壳侧面**：在外壳侧壁选一处避开散热格栅与开关孔的位置钻 2 个 M3 孔，把面板贴装上去；屏幕会略高于 36mm 的壳高，观看角度自己定。
4. **一定要嵌进顶盖**：这需要改壳体尺寸，二选一，告诉我要哪种即可 ——
   - **加宽外壳**：新增一套 150×76 的底盒 + 顶盖，电机座偏左、屏幕嵌右侧；原 01~05 全部保留。
   - **挪电机座**：把现有顶盖的电机中心从 (0,0) 移到 (-24,0)，屏幕放 +X 侧，同时把 04 锁板 / 05 独立板的孔位一起平移；改动最大，会让已验证的孔位检查全部重做。

### 装配步骤

1. 屏幕模组从**背面**嵌进限位框，正面朝视窗，四周压边压住 PCB 边框；8 根 SPI 线从下边缺口引出。
2. 4 个 M2 柱上小压片 + M2 螺钉轻轻压住 PCB 四角，别压到排线和柔性 FPC；也可以直接点热熔胶。
3. 左右 2 个 M3 孔把面板固定到选定位置，再按第 1 节接线（`3V3 / GND / GPIO10~16`）。
4. 上电先发 `V` 看四边白框是否完整，再按第 4 节把校准值写回 `TFT_COL_OFS / TFT_ROW_OFS / TFT_INVERT / TFT_BGR`。

> **实测优先**：35×42mm 模组外框与 30×35.5mm 可视区都是按 `1.83" / 240×284` 推算的估值，不是实物量测值。到手先量 PCB 长宽、可视区、8pin 排针位置，改 `tft_mod_w / tft_mod_h / tft_win_w / tft_win_h`，再双击 `Enclosure/regen.bat` 重新导出并自动跑 `verify_stl.py` + `verify_fit.py`。
